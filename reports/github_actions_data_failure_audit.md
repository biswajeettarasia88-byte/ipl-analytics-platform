# GitHub Actions Data Artifact Failure Audit

## Failure
`FileNotFoundError: [Errno 2] No such file or directory: 'data/processed/matches.csv'` located in `tests/test_database.py`.

## Root Cause
The GitHub Actions workflow executed Pytest, which subsequently tried to load the production datasets (`matches.csv`, `deliveries.csv`, etc.) at the module level in `tests/test_database.py`. However, as officially defined in `data/README.md` and explicitly enforced by `.gitignore`, all datasets in `data/raw/*` and `data/processed/*` are strictly ignored by Git due to storage limitations and repository hygiene rules. When CI ran in the fresh Ubuntu runner, the required data artifacts were fundamentally absent.

## Evidence
- **`data/README.md`**: States, "Due to repository size limits... the full raw Cricsheet data is NOT committed to this GitHub repository." It explicitly defines `src/ingestion/ingest.py` as the deterministic mechanism to populate the database.
- **`.gitignore`**: Hard-ignores `data/raw/*`, `data/staging/*`, and `data/processed/*`.
- **`tests/test_database.py`**: Asserts strict production counts (`len(df_matches) == 1243`).
- **`src/cleaning/transformer.py`**: Consumes `data/raw/*.json` to predictably compile exactly 1243 matches and >295k deliveries into `data/processed/`.

## Architecture Decision
**B. data/processed/matches.csv is a generated artifact that CI must create using an existing deterministic preprocessing/fixture pipeline.**

The project was strictly designed to have testing performed across the fully ingested production dataset, not an artificial subset. Thus, CI fundamentally requires the ETL pipeline to be triggered synchronously before Pytest.

## Exact Workflow Fix
Appended the deterministic pre-processing pipeline immediately preceding the Pytest execution layer within the CI definition in `.github/workflows/tests.yml`:
```yaml
    - name: Generate Data Artifacts
      run: |
        python src/ingestion/ingest.py
        python src/cleaning/transformer.py
```

## Verification Commands
The exact commands executed locally in a clean, reproducible environment mimicking CI were:
```bash
# Clean out local data mimicking CI checkout
Remove-Item -Path data\raw\* -Exclude "README.txt", "metadata.json" -Recurse -Force
Remove-Item -Path data\staging\* -Recurse -Force
Remove-Item -Path data\processed\* -Recurse -Force

# Execute workflow sequence
python src/ingestion/ingest.py
python src/cleaning/transformer.py

# Verify counts
(Get-Content data\processed\matches.csv).Length - 1 # Output: 1243

# Run validation checks
python -m pip check
flake8 src tests --count --select=E9,F63,F7,F82 --show-source --statistics
pytest -v
```
